# 第二轮训练标签与词汇覆盖诊断

2026-10-23。目标是区分关系建模、标签表示和候选召回的瓶颈，为三路线提供可以验证的方向。**只读取原 train64、指定 HPO 和训练内四折清单，没有读取 dev16/B 标签或候选预测；未修改评测口径。** 本报告不是模型成绩，不改变用户原 dev16 Score ≥ 0.8 的验收目标。

摘要数据、源文件和生成脚本 SHA 见[诊断 JSON](round2-training-diagnostics.json)，原固定口径及四折规则见[共享验证](round2-validation.md)。个体金标例子只存仓库外，不将文献号、患者号或单个例子的答案硬编码到模型。

## 关系是否必须来自最终实体输出

官方[任务说明](../competition/sources/2026-10-23/tianchi-information.md)将 Task 2 定义为“给定特定患者，识别出与该患者相关的表型概念，给出相关表型的 HPO 标识符集合”；关系评测比较患者与概念的映射。字段定义要求无 ID 关系保留原文文本。中英文说明均没有写出“关系必须是最终 `entities` 输出子集”的跨字段校验要求。官方基线采用实体后接关系的流水线，但基线结构不是所有方案必须遵循的约束。

本地验证器也未增加这一子集要求。合成检查中，实体输出为空而正确关系存在时，格式检查通过，关系 micro/macro F1 均为 1；实体两个分项均为 0。这只是实现行为检查，不是官方服务的实测结果。

训练数据仍高度支持“关系对应文中实体”这一语义结构：

| train64 中的原子患者关系 | 数量 |
|---|---:|
| 在同文献正实体概念中精确找到 | 1703 / 1717（99.185%） |
| 只在 `note=NO` 实体中找到 | 13 |
| 在任何实体中均未找到 | 1（畸形复合 HPO 字符串） |
| 仅靠 alt_id 归一化才能救回的缺失对应 | 0 |

因此，实体驱动的关系模型本身并非错误建模；**把关系候选硬截到当前低召回的最终实体输出，是额外且脆弱的实现假设**。可以让关系模型使用独立的高召回候选池，保留文本证据和患者归属，再分别校准实体输出与关系输出。不能据 14 条不一致学习“否定也输出正关系”，或把这点标注不一致当作主要漏召回的解释。

## 表示差异与异常规模

train64 有 64 篇文献、173 位患者、4920 条实体标注，其中正实体 4765、否定实体 155。去重后的正原子实体单元为 4828：有效 HPO 主 ID 4705、有效 alt_id 9、无 ID 单元 98、废弃 HPO 1、分支外 HPO 13，以及两个非法 ID 单元。还有 3 条实体的 `note` 为未说明的 `D`；当前 v2 将非 `NO` 标注视为正例，预测格式仍按官方的 null/NO 输出，不复制异常字段。

1717 条原子患者关系中，当前允许的 HPO 主 ID 为 1668、alt_id 为 3、原文文本为 40、分支外 HPO 为 5、畸形 HPO 串为 1。40 条文本关系全部能精确对应正实体的 `identifier=-1` 原文，共 38 种关系文本。未发现应该把关系中的 `-1` 字面量直接输出的依据。

**复合关系计数不是互相矛盾的数字：**

1. 原始关系列表共 1827 项，患者内去重后 1683 项。
2. 原始合法复合串有 26 项，展开得到 63 次原子出现；去重复合串后是 25 项、61 个患者原子概念。
3. 其中 2 个原子概念已经以单独 ID 出现在同患者列表中，因此不拆复合的朴素集合实际漏掉 59 个独立正标签，同时保留 25 个不该当作原子类别的整串。
4. 最终 `1683 - 25 + 59 = 1717`。旧记录的 63 是未去重展开次数，本报告的 59 是相对未拆分集合新增的独立正标签。

训练时，实体、关联和候选两端都应使用一致的合法复合拆分及 alt_id 映射，保留原始标注版本；不要只规范化一端造成错误负例。不要按任意分号拆自然文本或混合非法串。指定本体范围、原评测中 alt_id 的精确字符串处理和异常金标保持不变，这些小比例差异不足以解释当前到 0.8 的主要差距。

## 训练内词汇覆盖

以下统计的分母是 **4714 个有效 HPO 的正实体原子单元**，包含允许的 alt_id 并仅在本诊断中规范化。匹配时已知金标实体文本和跨度，检查正确概念是否存在于候选词典中，**是带有金标跨度的覆盖诊断，不是实体召回率、F1 或模型得分**。

词面键为小写英文词和数字序列，忽略标点；“复数归一化”复用首日本体规则的词尾启发式。HPO 全同义词包括各 synonym scope，不代表全部应无条件作为高置信预测。训练别名只取相应训练文献的正实体，匹配留出文献；没有以目标文献自己的标签构建别名。

| 正确概念候选来源 | 覆盖 / 4714 | 比例 |
|---|---:|---:|
| HPO 名称 + EXACT 同义词 | 2528 | 53.63% |
| HPO 名称 + 全部同义词 | 2686 | 56.98% |
| 排除当前文献的其他 63 篇训练别名 | 1864 | 39.54% |
| 冻结四折中对应 train48 的别名 | 1674 | 35.51% |
| HPO 全同义词 + 对应 train48 别名 | 2966 | 62.92% |
| 上一项的 HPO 词表再做复数归一化 | 3089 | 65.53% |

四折统计将每篇 train64 文献只作为一次验证文献，并只使用该折 train48 的别名；4 个验证折的 4714 个原子单元合并计数，没有对不同分母的百分比简单平均。其他 63 篇诊断另做逐文献留出，与四折统计分开。

train48 中见过概念 ID 的验证单元为 2698 / 4714（57.23%）。HPO 全同义词加 train48 后仍未覆盖的 1748 个单元中，1051 个概念在对应 train48 未见，697 个是见过概念但换了未覆盖的说法。仅记忆训练 ID 或表面词会遇到明显的开放词汇缺口。

如果放宽为全文任意段落中出现该概念的词面证据，不要求它等于金标实体边界，HPO 全同义词、复数归一化加 train48 别名能为 1671 条有效 HPO 患者关系中的 1176 条（70.38%）提供候选。此检查忽略否定、患者和词义歧义，是乐观候选可用性分析；不能当成关系模型的召回。说明仅调输出阈值还不够，语义标准化、缩写与组合描述处理值得优先投入。

## 可行动原则与评测审查

- 先修合法复合关联与两端 ID 表示，避免把已有正例训练成负例；用训练内文献分组验证收益。
- 本体规则保留高召回候选及其命中证据，再判断词义、否定和患者；不只扩大最终输出集合。
- 病例检索和 CRF 的关系部分可接独立候选池；实体跨度和患者概念集合分别校准，减少 Task 1 的一次漏检直接锁死 Task 2。
- 序列识别、语义检索或公开预训练模型应能处理训练中未见的 HPO 和表达；HPO 资源提供候选知识，不能把未见概念一律判负。训练折内别名与缓存来源继续严格隔离。
- 无 ID 实体需要真实跨度，关联需要原文文本；不能输出无来源的自由生成字符串。否定有上下文和患者作用域，13 条训练不一致只标记审查，不据此取消否定处理。

未发现 v2 给无 ID 实体增加了与官方文字明确冲突的 HPO 要求：金标 `-1` 的正确跨度可以匹配一个预测 HPO，错边界仍不匹配。文档级 `-1` 如何去重、alt_id 是否按同义 ID 比较，官方公开文本没有充分说明；当前 text/精确字符串口径继续冻结。

已知近似差异仍存在：官方文字说只评正文，v2 默认 all，而训练标注包含 477 个正摘要实体和 46 个正标题实体。当前 body 启发式会排除它们，不能直接认定该启发式就是官方过滤。另，本地验证器允许没有对应输出实体或原文证据的关联文本通过格式检查，**格式通过不等于证据充分**。这些均只报告，不修改原门槛或评分。

## 复现与检查

从仓库根运行，只有摘要进入 Git；详细个体标注差异外存：

```bash
python scripts/diagnose_training_coverage.py \
  --train ../patientphex-data/day1/train64.jsonl \
  --hpo ../patientphex-data/hp.obo \
  --inner-manifest docs/data/round2-train64-inner4.json \
  --output docs/campaigns/round2-training-diagnostics.json \
  --details-output ../patientphex-runs/round2-20261023/validation/train-consistency-anomalies.json
```

[脚本](../../scripts/diagnose_training_coverage.py)固定原 train64/HPO 的 SHA，检查内折训练与验证分离并覆盖原 64 篇。2026-10-23 已在新位置实际运行；计数与外部独立统计一致，验证了 1827→1683→1717、63→61→59 的守恒关系，以及无实体关系和无 ID 边界的合成检查。仅使用本机 CPU 和 Python 标准库，无模型训练或平台操作；运行耗时约 1.3 秒，含进程启动的工具观测值。
