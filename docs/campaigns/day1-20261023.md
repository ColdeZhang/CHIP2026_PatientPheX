## 目标与边界

唯一优化目标是比赛分数，不要求原创。优先调研并复用成熟方法、公开实现和比赛允许的模型/知识资源；仍按赛事的数据与模型约束执行。主线程负责数据、共同验证、筛选、提交和总台账，子代理负责各自技术路线及完整实验记录，失败路线同样交付。

本地资源：5 CPU 核心、约 17 GiB 内存、无本地 GPU、初始空闲磁盘约 30 GiB。用户随后提供了 MCP GPU 服务器：已找到两张无进程占用的 A30 24GB；一张给检索路线 Qwen3-8B，另一张由序列模型与语义路线明确交接、依次使用（按模型就绪时间调整顺序）。其余已有进程的卡不使用。各本地代理默认单线程；远端使用独立项目目录或只读现有解释器，不修改他人环境。

B 集无公开金标，不能在本地得到真实 B 分数。统一使用按 pmc_id 分组的 64/16 训练/验证划分（seed=20261023）；派生词典、别名、检索记忆、分类器仅使用训练折。验证金标仅供统一评测。通过筛选后可使用完整 80 篇重新拟合首版并生成 B 预测；这两种运行必须分开记录。

## 统一交付与筛选

- 每路线提供可复现 CLI、来源/许可证及资源说明、验证预测、四项近似指标、格式校验、关键错误分析、耗时与产物 manifest；淘汰也必须结案。
- 不复用归档代码、词典或预测。比赛数据以重新取得的官方文件为准；只有核验官方版本和哈希后才能采用历史同字节副本。
- 共同命令接口：`python solutions/<route>/run.py --train TRAIN --input INPUT --hpo HPO --output OUT --work-dir RUN_DIR`。实体/关联 schema 按官方格式，覆盖全部输入文献和指定患者。
- 验证输入去除 entities/association；只有训练折含标注。共用评测器是公开规则的近似实现，正文与无 ID 细节未知时报告约定，不冒称官方分。
- 先完成有效性筛选：解析/ID/患者覆盖/坐标/HPO 范围/泄漏检查必须通过；空输出或明显失效的模型不提交。
- 预先采用相对实用门槛：以第一条正确运行的本体精确方案作最低参照。其他路线若验证总分低于其 70%，且四项中没有任何一项超过参照 0.03，视为明显失败；记录原因，不消耗提交额度。门槛只用于首日筛除失效方案，不是官方达标标准。
- 其余合格路线按同一验证总分排序，并结合四项得分及错误分析判断；最多每路线提交一个首版，受当日真实剩余额度约束，不为凑五次上传差方案。
- 主线程独占网页登录和提交。提交前保存预测 SHA-256、分支/commit 和配置；提交后记录平台提交 ID/时间/接收状态，禁止重复上传。今天不轮询评分。

## 负结果与取舍

- 模糊路线的训练候选排除当前文献别名后，v2 为 .606179，低于 v1 .630949。v1 没有模糊匹配贡献；其收益来自别名及监督筛选/归属。保存问题与修正对比，选 v1，不掩盖该限制。
- BiomedBERT 在 A30 上固定 4 epoch，实际拟合约 59 秒、推理约 7 秒，Score .613313，低于 CRF .684734。没有继续扫参数，也没有为较差版本额外生成 B。
- SapBERT 冻结语义编码 Score .545275，四项优于 MiniLM .517843；选 SapBERT。患者归属仍明显弱于 CRF，不把预训练模型名称当作高分证据。
- Qwen3-8B RAG 代码和来源已准备，但远端 HF/镜像不可达、依赖下载约 0.1 MB/s。ModelScope 实测约 6.64 MB/s，完整权重仍需额外准备；本日停止本人安装/下载进程，使用已验证的 CPU 病例检索版本。未实际推理，不报告 Qwen 成绩，不据此否定 RAG。
