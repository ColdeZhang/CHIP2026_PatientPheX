## 统一交付与筛选

- 每路线提供可复现 CLI、来源/许可证及资源说明、验证预测、四项近似指标、格式校验、关键错误分析、耗时与产物 manifest；淘汰也必须结案。
- 不复用归档代码、词典或预测。比赛数据以重新取得的官方文件为准；只有核验官方版本和哈希后才能采用历史同字节副本。
- 共同命令接口：`python solutions/<route>/run.py --train TRAIN --input INPUT --hpo HPO --output OUT --work-dir RUN_DIR`。实体/关联 schema 按官方格式，覆盖全部输入文献和指定患者。
- 验证输入去除 entities/association；只有训练折含标注。共用评测器是公开规则的近似实现，正文与无 ID 细节未知时报告约定，不冒称官方分。
- 先完成有效性筛选：解析/ID/患者覆盖/坐标/HPO 范围/泄漏检查必须通过；空输出或明显失效的模型不提交。
- 预先采用相对实用门槛：以第一条正确运行的本体精确方案作最低参照。其他路线若验证总分低于其 70%，且四项中没有任何一项超过参照 0.03，视为明显失败；记录原因，不消耗提交额度。门槛只用于首日筛除失效方案，不是官方达标标准。
- 其余合格路线按同一验证总分排序，并结合四项得分及错误分析判断；最多每路线提交一个首版，受当日真实剩余额度约束，不为凑五次上传差方案。
- 主线程独占网页登录和提交。提交前保存预测 SHA-256、分支/commit 和配置；提交后记录平台提交 ID/时间/接收状态，禁止重复上传。今天不轮询评分。
