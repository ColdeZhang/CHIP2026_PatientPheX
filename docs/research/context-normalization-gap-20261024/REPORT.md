## 2. 历史供给：能加 ID，不等于有充足可修复错误

S4已保存的历史F0诊断：与正金标单HPO跨度完全一致778处，原ID正确768、Top8覆盖777；在实际允许重排的非exact/非NIL 78处，原正确71、Top8覆盖77。它提示**当时 CRF 已选跨度池**的可用规范化增量很小；这不是当前更强实体池的上界，也不能用它替代当前 train-only 供给证明。本次没有重新访问对应金标。

S11的当前 a465 train48严格嵌套池有44,865个精确跨度组，其中44,333单ID（98.81%）；仅116个组有正负候选竞争。这个事实只能说明在**原有 ID 候选不扩展**时分组 ranker缺少竞争监督，不能否定新候选召回。S6另记录训练侧41个 canonical exact-span漏原子在旧全池/精确字典缺失，Top-K是否补上仍未知；4个alt-ID口径差异另列，不当真实语义错误。

## 3. “Top3扩池负”实际是什么

S8是 **公开 PhenoTagger PubMed＋Bioformer 分类头的 top1–3 ID**，不是 SapBERT top3。固定旧跨度，机械加入两模型 current-valid ID及真实 p/rank/observed六列；保留旧键。四outer各有三套train32→16祖先。8个训练/输入池244,794→747,178行，跨度不增加；四fold HGB fit/infer共145.395秒。

固定.3 pooled Score **.725655389→.723467295**，四折均负，关系完全固定；mention净−5TP/+69FP，新增48TP/130FP、移除53TP/61FP。预定九点校准最高Task1均值 .777516517 仍低于旧 .780192596。**实测是“扩池＋新观察特征＋原HGB解码”的联合配置负；不能凭此单独判定新候选无供给，或断言另一 learned ranker 必然失败。** 也没有证据把失败归结为某个单一原因。

后续Sap对照不是重新召回Top3，而是给既有 candidate-ID补真实公开别名cosine（S9/S10）。资源已记录：16套nested/outer缓存288个npy约3.218GB；19,119 HPO、41,099公开name/EXACT词面；新增98,168种phrase-ID对。旧bank含训练别名及best_id，不能直接当公共all-ID映射跨折复用。补799个缺词面后，Top3池加两列Sap的最佳Task1均值 .778190379，旧池加同两列 .779111432，均低于旧 .780192596；这些是训练侧校准目标，不能叫完整Score或独立泛化。

公开PhenoBERT pair是词面＋HPO名的NotMatch/Related/Match，不含文内上下文（S12）；不应拿它冒充上述Top8上下文监督训练。

## 4. 决策与重开条件

**关闭当前宽泛重复提案，不申请新fit/GPU或原dev验证。** 现有证据不支持为了凑“未尝试方法”而立刻换loss、去exact保护或再扩K；这些变量理论上不同，但没有当前固定已选跨度的训练侧可修复供给、可靠困难负例以及预期收益支撑。

若未来另行重开，先只在固定train64→outer train48→各nested train32标签权限内证明：当前选中跨度中的错误 ID，有多少能由独立 Sap候选补回，且未被 exact/NIL保护遮挡。必须按当折训练别名重建映射，不能把外层/原dev别名或已有gold诊断例子带入候选选择；若进一步把CE分数交树，还要保持S6已证明必要的更深候选/CE祖先隔离。先有供给证据，再冻结一个真正新变量和匹配端点；本报告不据历史训练201.85秒声称当前四折成本已获保证，也不承诺收益。
