# 关系学习融合：已有历史与可用缓存

结论：**已经做过真正的学习融合，不能把“加一个 stacking 模型”当成尚未尝试的新方向。** `sft-meta1-fusion` 在 F1 的 1,557 对上拟合 HGB，用 LR 概率/决策、规则聚合/上下文 299 列，加同一 SFT 的四列决策事实形成 303 列，再评 F0 的 1,166 对。F0 Score 从新配对基线 **.673525489 → .683809711**，仍低于旧 SFT48 **.695443948** 和同池规则 **.711353522**；macro 较配对基线还下降 .010456。已有源码和结果都明确是单 meta-fold，不是完整三折 OOF。

四个 SFT 特征准确为 `llm_selected / llm_empty / llm_parse_failed / llm_selected_count`，来自**一个** SFT 的完整 JSON。旧公共列已有 `relation_lr_probability / relation_lr_selected` 和 `rule_selected_max / mean / min`。所以重新加入规则硬选择、旧 SFT 正负或换个“多特征融合”名称，不能直接算新信息。它也不是多个独立 LLM 各自预测的集合。

另一项确实已做：`binary_logit + old_sft_positive` 两特征 LR，F1 拟合后 F0 唯一期望 F1 解码，**.695443948 → .696545689**；micro/总体 TP/FP/FN 不变，仅 macro +.004406964。此固定配置已关闭扩大，不能忽略历史重做。旧 8B∪9B 直接并集则刚以 **.688565023** 负结案，是集合控制，不是学习 stacking。

## 还缺什么

当前能直接对齐的是 rules、LR、原 SFT、binary32 和同模型 reverse；其中前三已在旧学习融合中出现，binary 的两列融合也已做过。把 binary 与 reverse 一并加到既有 HGB 是一个尚未在本次有限历史中定位到的具体增量，但不是“第一次做 stacking”，现有负/微小收益不能被忽略。本次不提出参数搜索或启动实验。

真正新增的跨基座信息目前没有完整双折缓存：8B 缺严格 F1，Med 缺匹配 F0，R1 缺两折完整输出。患者优先的新因子分解有 F1，F0 需等待当前 owner 完整终点。只用 F1 16 文档作为 meta-training，可以让最终 F0 全链不见 F0；这仍是已反复研究的开发划分，不是盲测。若改成完整三折 OOF 元训练，需要各目标折对应的基模型与候选生成器都排除该目标及外层 F0，不能切旧 full48/full64 预测假装严格 OOF（H40）。

旧 HGB 的 F0 概率 `8489b5bc`（with SFT）/`f76e849d`（without）已存；它本身在 F1 上拟合，不能把该模型的 F1 回代值作为下一层的 OOF 特征。若堆更多层，还缺新严格交叉拟合的上一层输出；这与直接使用已经隔离的基模型 F1 输出是两回事。
