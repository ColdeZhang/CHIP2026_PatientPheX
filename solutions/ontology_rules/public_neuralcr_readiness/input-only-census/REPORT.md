# NeuralCR 训练输入候选工作量（无模型、无质量）

固定64篇四字段输入 `ee252384…`；直接从公开原生 `annotate_text` 提取 `get_match` 前的原AST，保留原规范化、1–7词和字符位置。未加载模型、读取phenotype/association标签、拟合或计分。首次只是过严metadata guard拒绝24个合法title字段；旧源/计划/失败保留，唯一修复为allowlist增加title。

CPU实际 **6.427秒**：2301段/683438原生候选坐标；414801个保留大小写的词串，按真实 `phrase2vec` 的token序列归并为 **408272** 个键。全部原文坐标roundtrip和6个人造反例通过，0个空候选段。唯一查询表在仓库外，大小/SHA见report；不是已预测的HPO表。

旧两种公开模型canonical共有11933行、6787个不同坐标；其中6542在NCR raw枚举、245不在。新raw坐标相对该旧集合有676896个，仅为**未评分供给差集**；阈值和重叠消解依赖尚未运行的NN分数，不能把此数当新实体、TP或召回。旧模型的logits不能供NCR复用；旧完整raw词串表只在服务器，没有在连接故障中另行拉取，故未报精确raw key交集。

408272个键对应原生512批量约798批（固定50×100输入、10 ensemble、14261输出）。尚无匹配的真实batch耗时，不从本次枚举CPU时间推断NN运行预算。完整资产/参数/四合成native尚待MCP恢复补缺；只有native接口通过后才能考虑首次真实全缓存，当前不启动赛事NN。其后采用NCR时须真正替换BioBERT来源及6字段、fresh HGB，不能沿旧103列模型扣掉BioBERT参数。
