# 公开 PhenoTagger 已缓存 top3 / 字典多 ID 供给诊断

主线程授权的训练侧低成本上界：在既有 298 个“跨度已存在但缺正确 literal ID”的 FN 原子（287 个跨度）中，检查 PubMed/Bioformer 固定 raw top3 及原生字典多 ID 是否包含目标。仅研究是否值得随后统一扩展 ID 候选；这些 gold 查询不构成正式候选策略，不输出新预测/指标，不 fit、不读 originaldev、不加载权重或使用 GPU。

先远端实查三个 raw 文件可读（总约 368 MB），各 1,000 行解析约 0.012–0.014 秒，两个 17,266 列 label 文件相同，固定 head→current 和 dictionary→current 映射 SHA 均通过。只在远端扫描原缓存，不回传大 raw；CPU 硬限 120 秒。全文输入严格是已投影的 train64 四字段无标签副本，唯一诊断目标来自已冻结 `.3` 与旧候选池。

固定 top1/top2/top3、两模型分别/并集；不另选 posterior 门槛。映射仅作用于预测资源，gold 按 v2 原样 ID，复合原子分母不变。原 raw 不含的跨度单列，通过既有 native tokenizer/坐标区分 unigram、2–8gram 被过滤、超过上限及非词边界，不把它们称为 top3 分类失败。按原生字典实际匹配重放 first-ID 并与缓存一致后，检查其固定多 ID 列表中的后续 ID，区分“首 ID 已正确”与“仅后续 ID 正确”。

[冻结计划](../evidence/round2/public-phenotagger-top3-plan.json)记录所有源、缓存/映射、查询 SHA、预算和恢复路径。原生 hybrid/缩写/否定/greedy 未用新 ID 重解码；此处只是 raw 供给，不能称可实现的分数或独立泛化结果。已有放宽跨度候选后 1,697 个真正新 pool 键 0 接纳的负结果提示：即使新增 ID 有覆盖，也需另查 selector 是否具备区分它们的特征，不能直接扩大正式池。

276 个查询原子在两个模型都有准确 raw 跨度，22 个没有：19 是 native unigram，2 是对齐的 2–8 token 但被原候选过滤，1 是非对齐词边界或跨句。缺 raw 不计为模型 top3 分类错误。旧 head 原字面包含 282/298 个目标；固定 current 映射后可输出 literal 目标为 273，25 项不可达，其中 9 项原 head 曾有但已映射走。29 个 FN 原子来自 18 个多 gold-ID 跨度，不能假设所有原子能被单实体输出同时恢复。

字典在 26 个查询原子处有完整匹配，全部只有一个原 ID，正确目标均不在其中。因此在这 298 项里，解除原生 first-ID 歧义截断的额外供给为 **0**；不能以此否定其他数据上的字典歧义问题。

## 下一项的最小可测建议（未执行）

已冻结 HGB 的同 ID/跨度信号包括本体/Sap 分数、exact/base/same_base_id，以及该 ID 在当前文档 base 内的频次；后者并非训练 HPO prior。两个公开模型各自只有六个 native 来源/混合 score 特征，原始 ID/head 列只留审查元数据。当前四折 `crf_confidence=None`，默认 0 的 CRF 后验字段不能当成实际导出的概率。现有特征没有每个 HPO 的真实 NN posterior、rank、margin 或 HPO 名称/同义词词面相似度。

因此，不带真实 ID 区分证据地加入同跨度多 ID，可能产生完全相同的特征向量和同分，再由稳定排序碰运气。建议若另开控制，先只在**全部原冻结候选跨度**上统一加入缓存 top1–3 的有效 current ID、保留全部旧键，不增加新跨度、不按这 298 个 gold 查询选词；先 CPU 核规模和特征区分性。最少加入每个模型的真实观察列概率、观察排名和缺失标记，保留模型来源分离；多个旧列映射同 current ID 时可记实际观察 max-column 概率/min-rank，但不能称其为完整 canonical 类 posterior，未观察的分数也不能伪造。

这会同时加入部分被早筛的 raw top1 与低 rank ID，并改变选择器特征，须按组合候选/特征控制披露。只有在规模和接口可行后，才另冻结一次严格嵌套 OOF 对比，不凭本次错误条件化覆盖宣布质量提升。**本次未生成该统一池、未 fit、未新增分数。** 源码静态核验与跨路线确认使用同四个固定文件快照；[结果/恢复索引](../evidence/round2/public-phenotagger-top3-results.json)包含实际输出、查询、源码、旧来源及特征说明。独立增量审查PASS（`95f38f35…`）：重新构造298/287查询并复算小聚合，实际大raw/代码SHA绑定；审查未再次扫描368MB或重跑tokenizer。字典26查询原子对应21唯一跨度。随后统一池准备单独记于[E-20261023-PUBLIC-PHENO-TOP3-ID](E-20261023-PUBLIC-PHENO-TOP3-ID.md)，不改本诊断边界。
