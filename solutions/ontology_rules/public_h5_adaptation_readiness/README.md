# 公开 PhenoTagger H5 监督适配：源码可行性盘点

只做源码、原生类别映射和既有覆盖报告核对，没有数据准备、模型导入、训练、GPU或新质量结果；实际反向、梯度有限性与训练显存尚未验证。后续优先级仍低于当前官方B和已经授权的全文关系路线。

**判断：接口可行，但尚不具备训练启动合同。** 当前实际TensorFlow2.12私有环境已有原生H5严格逐变量加载证明。原图是phrase-only、lowercase、maxlen32、CLS→17266类softmax，可以在准确加载后再compile/fit；上游 `BERT_training` 本身没有先加载公开H5，直接调用会是从基座/新分类头开始，不能当公开成品权重继续适配。

已结案的100ep＋1749词面回放3ep使用自训Biomed及2026新19120类头，和完整公开17266类H5起点不同。旧builder硬绑19120类且HP:None在0，公开头HP:None在17265，不能沿用原builder索引。它只重复正例词面并保留HPO/None回放，明确不把NO、NIL追加为None。已知负结果足以反对照搬该词面配比，不能证明公开权重上的任何监督适配必然失败。

已有train64粗类覆盖报告可直接复用：4765条正例记录，4665 linked、100未链接或非HPO；4626 linked记录至少一个canonical ID在原head，4623全部ID在head；155 NO被排除。原head17266列含末列HP:None，17262原HPO列可映射至17090个现行HPO，存在多原列映射到同canonical类。这个历史报告使用startswith('HP:')与alt映射，包含格式/分支例外；数字不是新训练集规模，也不是每折严格可监督数量，更不是分数上界。

正式准备前必须明确的三件事：

1. **目标语义**：`-1`表示真实未链接表型，不能当HP:None；现行HPO缺原列、复合ID、同canonical多原列的监督都要先定义，不能随便选列或换头冒称原模型。若保持全原列，需冻结如何表达多目标/等价类的loss。
2. **负例与可辨性**：原模型看词面，不看其句内否定。NO与肯定可能共享完全相同lowercase/token输入；把NO直接标None可能制造矛盾，实际碰撞尚未计数。边界难负例也需核训练折内与真实正跨度、合法嵌套/跨文献词面的冲突，不能无条件把所有重叠非exact候选都当None。
3. **收益传导**：字典生成不在神经图中，后续分数/重叠合并可受影响，但调神经分类器不等于学会拒绝字典误报。当前103列LGB依赖旧公开模型分数，NN适配后的分布迁移必须在完整固定融合端点验证；不能以phrase训练accuracy替代Score。

合理下一步是一次训练折内CPU样本/类映射/输入碰撞census，再由实测规模冻结单模型、单配方工程预算；目前未选模型、未制备样本、未运行此census，也未授权GPU适配。源码和既有证据SHA见 [evidence.json](evidence.json)；限定历史搜索未发现公开H5继续监督适配实际终点，见独立 [history-review.json](history-review.json)；未发现不等于穷尽所有历史。
