# 整患者 HPO 集合 SFT：训练内可行性研究

结论：可以准备一个“每个患者读取完整原文、直接输出其表型集合”的小规模对照。train48 的完整原文无需裁剪即可落在 12,288 tokens 内；逐患者方式的总 token 数与现有候选关系 SFT 相近。开放输出可越过候选召回上限，但 HPO ID 生成及患者归属仍有风险，不能据预算判断它会涨分。本研究未训练、未生成预测、未使用 GPU，也未读取 fold0 或原 dev 的 gold。

## 先澄清来源

官方综述 `overview.txt` §3.3 写的是 **Qwen3-8B zero-shot**：先识别患者共指，再对每批 8 个表型候选提供前后各 500 字符判断关系，明确没有 SFT。“直接生成患者 HPO 集合 + 候选对二分类 SFT”出现在 §4.2 **第二名医诺未来的 Qwen3.5-9B** 方案。Agriv 模型卡确认 Qwen3-8B 患者阅读 LoRA 和五折模型，但未给其完整目标 schema。因而本提案是受成熟方案启发的自建对照，不能写成复现官方“集合 SFT”。

来源：[比赛官方仓库](https://github.com/DUTIR-BioNLP/PatientPheX)、本地已核验综述 `/workspace/patientphex-runs/round2-20261023/research/overview.txt` 与 `agriv-model-card.md`；文件 SHA 见[研究证据](patient-set-sft-feasibility.json)。不下载用官方 80 篇训练的成品 adapter，以免污染 train48/内部验证隔离。

## 已核验的数据事实

- train48：48 篇、126 位指定患者、417 条给定 mention、1,338 项原子患者关系；22 篇为单患者，7 位患者的表型集合为空。每患者关系数中位 8.5、最多 44。
- 当前关系 SFT 为严格 outer-train48 内三折 OOF 候选，204 行、1,477 个概念决策、4,127 个患者候选对（967 正、3160 负）。**371 / 1338 = 27.73%** 训练关系不在候选集合；其中 362 项能在同篇找到对应正实体。因此只将 `候选→患者` JSON 转置成 `患者→候选`，无法恢复这 371 项。
- 有 792 个不同关系值，其中 533 仅出现于一位患者，615 仅出现于一篇文章。没有证据说明 48 篇足以学会对未见表型自由生成正确 HPO ID；预训练知识和标准化能力是开放集合方案的真实缺口。
- 原目标含 1,313 项语法完整 HPO ID 关系和 25 项其他字符串。前者有 4 项不属于指定 HP:0000118 分支；后者 24 项是全文中的原始未归一化表型字符串，1 项为畸形 `HP:0003645;HP:000328`。四个分支外项为非表型异常分支的病史/修饰概念，不是已证实可替换的过期 ID。**不补猜数字、不将畸形值假装成原文表型，不悄改评测标签。**正式训练构建时须单列这 5 项异常及采用的输出约束；本研究未生成正式训练文件。
- 现有训练内患者锚点审计显示：967 个候选内正关系中，363 个局部证据没有目标患者 marker，尽管全局锚点仍在。关系标签没有“这项关系对应哪个 mention”指针，不能据文档级关联把某个局部窗口强标为患者证据。完整原文避免裁窗造成的可见文本遗漏，但不能证明每项关系证据都存在于提供的文本中；9 项关系连对应正实体也未匹配。

## 实际 tokenizer 预算

使用已固定 revision 的 Qwen3-8B tokenizer，`enable_thinking=False`，与训练器相同的 chat template 和 assistant 前缀检查。按原始 `full_text` 顺序保留**所有**段落，标注全部给定患者 mention；为一位目标患者建立一条预算探针，共 126 条。没有候选提示表、示例检索、额外共指或表格补充。预算探针保留原目标异常值以保守计数，不等同于已批准训练数据。

| 同口径：一轮未 padding 的完整 chat token | 全文患者集合预算 | 已有逐候选关系 SFT |
|---|---:|---:|
| 样本数 / 文献数 | 126 / 48 | 204 / 48 |
| 总 tokens / epoch | 640,031 | 661,265 |
| 平均 tokens / 样本 | 5079.61 | 3241.50 |
| 最长完整样本 | 10,419 | 5799 |
| 最长 assistant 答案 | 451 | 116 |

患者集合方案 prompt tokens 为 625,330，assistant tokens 为 14,701；完整长度中位 4670，10 条超过 8192，0 条超过 12288。126 条 prompt/full 前缀完全一致，无截断。两轮约 1,280,062 原始 tokens；有效 batch8 时每轮 16 个 optimizer steps，两轮 32 steps。总 tokens 比现有方案少约 3.21%，**不代表耗时或显存相同**：单序列更长，attention/激活峰值更大。A30 的短序列 smoke 不能证明此配置可训练；若决定启动，先在空闲 A800 上做最长序列 smoke，不能先截断让其通过。

CPU 审计未加载模型，仅加载 tokenizer；`CUDA_VISIBLE_DEVICES` 为空。[实际命令与返回](patient-set-sft-token-command.json)、[统计/来源 SHA](patient-set-sft-feasibility.json)、[训练内审计源码](patient-set-feasibility-audit.py)。全文预算探针 SHA 为 `dfde8888041025cbbf63064015b91f13b1cddf099ccbc5545750797bb5a0953b`，外存 `case_retrieval/patient-set-feasibility/`；不将 2.6 MB 原文探针放进 Git。

## 建议冻结的最小方案

1. **输入与身份**：一条样本对应 `(pmc_id, patient_id)`，把本文患者 ID 映射为 `P001...` 并在精确原文 mention 插入 marker；显示全部患者，明确唯一 TARGET。附所有原始段落及 section/offset，不按 gold 或候选挑窗口。训练标签仅在输入冻结后序列化。无需把同一全文切块后给每块重复整患者 gold；这种做法会让没有证据的块接受正监督。
2. **输出 schema**：`{"hpo_ids":["HP:000...."],"unmapped":["verbatim phenotype"]}`，两数组去重；7 个空患者保留空数组监督。`hpo_ids` 只允许指定版本/分支内有效 ID；`unmapped` 对应官方未归一化表型原文，不能输出抽象 `-1`、杜撰 ID 或将任意非法值转为字符串绕过约束。最终 association 是两数组的集合。训练异常 4+1 单列，不能自动猜修；正式样本构建前固定处理方式。
3. **候选与未知项**：首个最小对照不放候选硬限制，以便检验开放召回。生成的有效 ID 即使不在 Task1 实体池，也不能再被候选闭集过滤，否则研究问题改变；未知/非法 ID 拒绝，未归一化项要求能在原文精确定位。开放输出会产生规范化和幻觉风险，此轮先保留错误类型，不叠加新 linker、阈值、投票或患者共指方法。必要时后续单独研究带 HPO 检索提示的版本。
4. **训练配置**：继续固定 Qwen3-8B 同 revision，7 投影 LoRA r16/alpha32/dropout.05、BF16、assistant-only、seed20261023、lr1e-4、batch1×累积8、2 epoch、gradient checkpoint、max_seq12288、禁止截断，保持在 10B 以下。选择 epoch002 预先冻结，不在验证结果中挑 epoch。126 行/48 文献的预算尚未验证训练显存或学习效果。
5. **隔离与比较**：按文献隔离全部患者、全文、候选和派生提示。训练中有 20 种 patient_id 字符串跨文献重复，影响 107/126 位患者，故绝不能仅以 `patient_id` 去重或划分。给定数据没有跨论文的真实人物全局 ID；本次 train48 内 ≥150 字符规范化整段查重为 0，不足以排除同一人被多篇报道。若输入级查重发现跨折重复病例，应报告而非擅改固定划分。后续对验证输入先做无标签长度审计；超过预算时显式失败，不偷偷裁掉后文。

## 对照能说明什么

与已有逐候选 SFT 相比，这个新方案同时改变了 **证据范围（局部→全文）、输出空间（候选闭集→HPO 开放集）、解码方向及样本权重（概念批次→每患者集合）**。固定 base、LoRA、文献和训练轮数只能构成路线级对照，不能把任何增益单独归因于“集合 schema”。保持 Task1 实体预测不变，只替换 Task2 association，用同一评测器观察 mic/mac-F1 与总 Score；随后若确有收益，再做同输入/同候选空间的输出方向消融。此阶段没有本地或官方新成绩，是否进入训练及与 fold1 复验的顺序由主线程决定。
