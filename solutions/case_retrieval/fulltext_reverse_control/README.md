# 旧 SFT32 全文输入的候选逆序

有限历史核查未找到同一旧 `4f4815b6` 适配器对**完整全文 80 提示本身逆序**的实际终点。已有短提示逆序、正序全文、缓存四源并集和重新训练的顺序增强；它们均不是这个输入控制。核查范围与精确历史引用见 `history-inventory.json`，不宣称已证明所有服务器上都没有其他实验。

本控制复用正序全文完整输入 `2a95bad1`。原候选逆序的三个函数保持源码字节一致；先仅变换原短提示候选块，随后逐字节拼回已经冻结的全文后缀。原 system、患者、候选证据及概念集合保持；CID 只在对象顶层替换，原文及嵌套内容中的 CID 字面量不改。双逆必须恢复完整原行及后缀字节。

`prepare_cpu.py` 只准备输入：固定 60 秒、GPU 隐藏，不读训练标签或新 gold，不加载模型权重。先核旧正序全文 native IDs/往返及旧审计，再核逆序全部 80 行。生成固定提示、IDs、双向 CID 映射、完整原文后缀 SHA，以及最长提示。输入 cap 按实际最长 tokens 向上取 512 整数倍，保留输出 1600，核完整上下文容量；禁止截断。输入路径、base 与输出目录均显式参数化。

```text
python prepare_cpu.py --plan contract.json --base <已核Qwen3.5-9B>
  --input-dir <三份原文件的暂存目录> --output-dir <新的CPU目录>
```

三份原文件 basename 为 `meta.prompts.jsonl`、`expanded80.jsonl`、`row-audit.json`；暂存路径可变，原大小/SHA 不变。未来最长 GPU 探针由父线程另外绑定并启动，240＋TERM30，原 BF16/native SDPA/greedy1600；这里没有 GPU launcher。

预定 primary 为正序全文∪新全文逆序，diagnostic 为新全文逆序 alone。两份完整预测共同冻结后分别唯一 v2，旧基线 `.676546354662594` 复用，不重评分；Score 严格升才支持保留，macro 和全部分项照实报告，不更换臂身份。原 1189 实体及非关系字节保持。该 F1 已用于多轮开发，不称盲测；缓存正序运行在 A800，新逆序计划在 A30，设备/后端数值差异是明确限制，不称完美单变量数值对照。

当前仅完成两份源码 compile、三个旧逆序函数源码相等与合同准备；没有运行 tokenizer、远端、GPU 或质量。
