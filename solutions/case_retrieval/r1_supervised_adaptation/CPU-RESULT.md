## 研究依据与数据边界

官方综述 §4.2 只披露冠军使用 Qwen3-8B、DeepSeek-R1-0528-Qwen3-8B 的预测、上下文/位置特征、LightGBM 与五折 OOF，**没有披露这两个 LLM 是否做过 SFT/LoRA**。明确写出的 Qwen3.5-9B 生成式及二分类微调属于第二名，不能归到冠军。本任务是新的监督适配假设。

沿用严格 F2+F3 的32篇、124条原闭集 JSON 训练数据；候选生成分别为 F2→F3、F3→F2，各只训练16篇，排除整个 F0/F1。原80条 F1纯输入及 CID/PID 字面身份保持。原 R1 集合和元模型 OOF 负结案不因此重开。

## 实测通过的 CPU 合同

- 发布模板以 `<｜Assistant｜>` 收尾，**没有预先打开 think**。124条完整字符串编码的提示前缀、原 JSON 答案及原生 EOS 全部精确一致；不添加思维链或空 think。80条 F1输入 IDs 与已有正确发布接口合同完全相同。
- 训练总计401,291 tokens，其中监督7,046；最短570，最长 **5,519**（`11235872:relations:8`，索引6）。全部低于预设拒绝上限8192，无截断。不能沿用旧 Qwen3.5 的5523长度。
- 两权重头共399 tensors；基座 **8,190,735,360** 参数。仅 meta 构造实际 `Qwen3ForCausalLM` 与 r16/α32/dropout .05 LoRA，七投影共252个目标模块、**43,646,976** 可训练参数，总数 **8,234,382,336**，低于单模型10B。head/embedding 冻结；无真实权重值载入。
- 已确认实际 forward 可到达实例 loss hook。float32/BF16、带/不带显式分母的4项合成 logits 比较中，selected-CE 与原生 CE 的 loss 相等、最大梯度差均为0。尚未跑真实模型 forward/backward。

BF16 基座加假定 FP32 LoRA 权重、梯度及两份 Adam moments 的静态驻留下界为 **17,079,822,336 B（17.080 GB）**；它不含激活、临时张量或分配器开销，**不是显存峰值，也不证明 A30 24GB 可训练**。CUDA 未初始化，optimizer steps=0、quality calls=0，未读 F0/原dev gold。
