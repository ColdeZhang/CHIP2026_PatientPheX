# 训练标签条件下的患者归属理由蒸馏

**存在尚未实际试过的机制，但目前只够支持训练集供给探针，不够直接启动蒸馏训练。** 建议研究“带原文引用的短归属解释作为辅助监督，预测时仍直接输出关系”。它区别于零样本长思考、直接标签 SFT、nearest 弱 quote 和 DPO。当前没有证明缓存模型能产出足够忠实的理由，更没有新的质量分数。

## 新信号与已试方法的区别

已沿实际源核查：R1 `cpu_contract.py` 131–173 行明确原 JSON+EOS 监督、无 think；G `prepare.py` 以距离选词面并标 `attribution_is_weak_assumption=True`，`schema.py` 明示 quote 只是概念定位而非患者归属证据；RAG `prepare.py` 保留原标签 JSON；DPO 只对同 CID 的患者标签作合法交换。已完成的公开 R1 full80 thinking 只有推断结果，不产生训练理由。对这些实际训练路径未见 teacher rationale 蒸馏；这是有界查重，不宣称所有历史文件的全局不存在证明。

新的监督应包含**为什么这组患者锚点和这段表型描述属于同一病例**，例如组内成员的共同表型、代词衔接、病例段落的身份承接。不能把更长输出或“根据金标答案解释答案”本身当新证据。

只读检查固定选择中的前三例，发现一个真实可解释的训练机会：PMC11235872，目标 OII-3 / HP:0001250。原文先列“individuals II-2, II-3, and II-4”，下一句写“All had an almost identical epilepsy phenotype…”。这里需要组内身份衔接；nearest 几何不能充当这条衔接。此例仅表明原文可能支持这样的监督，不是模型已能生成它的证据。未据阅读更换任何选择。

## 成熟方法与本项目适配

[STaR，Zelikman et al.，2203.14465](https://arxiv.org/abs/2203.14465) 实际提出：错误回答可在正确答案提示下重新 rationalize，再用答案正确的理由训练。**答案正确筛选不保证理由忠实**；本项目不能照搬其接受规则当作患者证据验证。

[Distilling Step-by-Step，Hsieh et al.，ACL 2023](https://aclanthology.org/2023.findings-acl.507/) 用标签预测与理由生成两个任务共同监督。[作者实现](https://github.com/google-research/distilling-step-by-step/blob/ef944263c9ddfd40a9888557f3e7d17513fd1a7e/model_utils.py) 是 `alpha*label_loss+(1-alpha)*rationale_loss`，README 推荐 alpha=.5；Apache-2.0。它用不同任务前缀，预测阶段可只输出标签。本项目可采用这点，避免强制在每条比赛推断中生成长理由。论文的 PaLM→T5、四项 NLP 基准不证明 8B 自蒸馏或本比赛能涨分；没有下载其外部标注数据。

若供给成立，学生可复用已核 train32 原生 Qwen3-8B parent543c，保留完整原124 JSON 标签任务，另加审核后的归属证据辅助任务；这是跨模型弱理由监督，不是把教师权重或训练标签放到推断提示中。**现在不冻结训练损失权重、轮数或完整质量终点**，因为可用理由数和长度尚未知；不得由本报告直接启动 SFT。

## 成本与未解决风险

当前仅构造文本：15 条共328167渲染字符、最大37201字符；尚未进行原生完整 token 编码，因此不能声称真实最长长度、显存或 GPU 预算过门。旧 R1 full80 106142 输出 token /3431.089 秒生成，约30.93 token/s；15×3072 的输出上限按该旧平均速度约1490秒，**只是代理，不含更长全文 prefill/加载，不能当限时保证**。建议若 root 认为值得，先实际完整 CPU token 长度门，再按同卡 fresh 工程/成本确定一次供给窗口；不以裁剪最长报告过门。
